# 配信運用 UI188 の導入と互換性

配信枠の作成には担当 Encoder と Worker が必要です。`streams.create` に加え `services.assign` と `workers.assign` を確認し、枠・ビジュアル・両担当を同じトランザクションで保存します。オフラインのサービスも予約できますが、開始可能かどうかは別の Readiness 確認で判断します。未選択・他枠使用中・型違い・権限不足は保存前に拒否します。旧 caller の未割当作成と直接 archive 設定による新規作成は拒否し、録画プロファイルを指定してください。既存の枠設定は保持されます。

通常停止の ACK は、要求前の `updated_at` と対応する記録を残して確定します。応答を失った UI はこの記録を読み取り、停止を自動再送しません。後続の配信が既に始まっていれば、その現在状態を表示したまま前の要求を確定します。通常停止・強制停止とも未確定の間は割当と削除を保護します。強制停止がすべて確認された場合だけ保護を解除し、通常停止の ACK を偽造しません。録画確定待ち・固定 Relay の保護・他枠の所有権は継続します。

BOT は自身の primary 割当が選択されたときに Gateway を接続し、待機枠の VC を監視します。既存在席と入室イベントは同じ割当世代・重複抑止を通して開始します。未選択で idle の BOT は接続を閉じ、他枠で稼働中の正規接続は維持します。

フタは枠に最大32候補を保存し、開始時の候補と手動切替の候補を選べます。同時に表示する画像は1枚です。migration `084_stream_cover_candidates.sql` は既存の1枚を候補へ移し、既存ビジュアルの revision を変更しません。保存済み候補は画像の snapshot なので、元の preset が更新・削除されても保持されます。表示中・確認待ちの候補と履歴から参照される画像は削除・GCを保護します。

導入は Contracts の exact pin を含むビルドを準備し、Encoder・BOT の対応コードを配置してから Control Panel と migration 084 を適用します。旧 Control Panel への切戻し時も migration のテーブルや保存状態を削除しないでください。配置・サービス再起動・本番 migration は別途運用手順に従って実施します。

設定プレビュー、Encoder の反映確認、実映像の HLS プレビューは別の情報です。「反映を照合中」は成功ではありません。操作履歴と通知は要求・成功・失敗を区別し、内部 action ID は変更しません。操作確認はボタンで行い、認証・2FA・CSRF・権限・直前再検証・重複抑止・監査を維持します。
