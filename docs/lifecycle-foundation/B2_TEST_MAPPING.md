# S12-B2-B test mapping and limits

This mapping preserves the original B2-A T01–T40 identifiers. It describes the candidate's authored checks; it does not declare the original forty requirements complete. The authoritative required root-test inventory is `scripts/ci/b2-required-tests.txt`. Final workflow URLs, checkout/tree identity, executed root/subcase counts, Skip/Fail counts and final results must be attached to the final verification record.

**Execution state at authoring: CI_PENDING.** No local Go test, SQL test, Race run, cross-build or gofmt execution is claimed here. `SUBSET` means an authored check covers only the stated part of the original requirement. `REQUIRED_CLOSED` means a negative check or source guard rejects explicit L2 use; it does not prove the corresponding successful operation. `SOURCE_ONLY` means source/structure was inspected without an execution case for that behavior. `NOT_RUN` identifies behavior for which this candidate supplies no complete execution evidence.

Final local review also added `TestB2IdentityConfirmedReadDenialCompletes` (missing/expired Session is a completed unchanged read, not Deployment UNKNOWN), `TestB2IdentityLegacyFactorCannotEscapeParticipant` (an unconfigured factor owner cannot autocommit inside an active private participant), and `TestB2HTTPIdentityUnknownUserState` (unexpected User state never becomes an authenticated current User). These remain CI_PENDING and do not complete physical cleanup or public HTTP composition qualification.

## Evidence boundaries

- Untagged `internal/lifecyclefoundation/identity_test.go` and `identity_checkpoint_unit_test.go` test DTOs, exact class/operation rules, canonical compatibility, private request lifetime and the unqualified projection contract. They do not execute a product SQL owner.
- Tagged `identity_export_test.go`, `identity_integration_test.go` and `identity_process_test.go` use `lifecycle_identity_integration`. The fixture refuses a missing/non-Actions disposable DSN and an existing product namespace. All Users, credentials, proofs, ciphertext fields, tokens and ledger records are synthetic. The fixture's full-row capture exists only in `_test.go`; its opaque references are not an adopted production secret-commitment profile.
- `internal/httpapi/server_identity_lifecycle_test.go` exercises real HTTP middleware/handlers and the real `ServeHTTP` composition boundary with explicit fake AuthStore results. It does not combine the complete HTTP login flow with MariaDB. Successful Store tests must not be reported as successful end-to-end HTTP authentication.
- The test-only schema contains minimal actual MariaDB tables and per-DML epoch triggers. The Role test observes actual multiple trigger increments in that fixture. It does not replace production migration/trigger qualification or certify the full production foreign-key graph.
- The process helper is named `TestIdentityProcessHelper` and is invoked explicitly by child processes. It is excluded from the mandatory `^TestB2` inventory so a no-op helper invocation is not counted as a substantive root test.
- All explicit product Identity composition remains unavailable. In particular, successful HTTP login/refresh/password/administration/Policy/OAuth/MFA/Passkey/Email flows are not qualified by a configured fixture Store. The composition boundary rejects the unsupported routes before their external ports can run.

## Deferred guarantees

System cleanup operations have typed purpose rules but no implemented cleanup owner. The rules and negative tests are not evidence of cleanup participation. Actual OAuth/Provider/Policy/Secret participation, TOTP enrollment/challenge proof consumption, Passkey/WebAuthn state and Email/SMTP stages remain required-closed or unconnected as recorded in the connection inventory.

`CompleteIdentityLogin` and `ChangeIdentityPassword` are new local participation APIs around existing operations. The stale snapshot tests are post-change assertions. No run of historical vulnerable code, historical failing test or before-change race reproduction is claimed. Ordered disable→password and disable→refresh tests do not become simultaneous Barrier races by inference.

The User/FK tests prove atomic rollback/cascade behavior for the exact test schema. They do not certify every production child table, migration, RESTRICT/SET NULL edge, old writer, direct DBA writer or deployment topology. Source reconstruction and unchanged migration files remain necessary but do not replace environment qualification.

D4 has not adopted a production secret-state commitment, Key/Root/Rotation profile or qualified clock. Hashing fixture rows in `_test.go` is not that adoption. No real Provider, credential, approval origin, host independence, production migration, Bootstrap, Recovery workflow, Evidence issuance or product-wide L2 acceptance is certified by this mapping.

The existing status remains: **L2 deployment NOT_QUALIFIED; real L2 NOT_RUN; product-wide acceptance NOT_RUN; Phase 1 closure held; production migration unauthorized; formal v2 return NOT_CERTIFIED.**
